# 市场发现：从需求到候选模型清单

SKILL.md「两个入口场景」的选型支撑页：客户还没定模型（场景一）或定了模型没定版本
（场景二）时，怎么从市场上找到适合这台机器的候选。流程与实测结论 2026-08 核对。

## 第 1 步 · 需求画像

访谈四问的答案落成一行画像，后续每个候选都对照它过：

| 维度 | 取值 | 影响 |
|---|---|---|
| 用途 | 编码 / 写作 / 翻译 / agent | 决定题库侧重与模型系偏好；编码看 C/E 类，agent 必测维度三 |
| 主语言 | 中文 / 英文 | 投机解码加速比强依赖语言（英文数字可比中文高 2 倍以上，见 methodology.md）；中文用户以中文数字决策 |
| 速度 vs 质量 | 二选一排序 | 决定模型规模与量化位宽的取舍方向 |
| 隐私敏感度 | 哪些数据不出本机 | 决定是否必须全本地、可否用云端补位 |

## 第 2 步 · 候选来源

| 来源 | 用法 | 注意 |
|---|---|---|
| HF trending / 搜索 | 看近期热门与同类模型 | 热度不等于适配本机，逐个过第 3 步预检 |
| mlx-community 组织页 | MLX 官方社区量化，mlx-lm 首选来源 | 同一模型常有 4bit/6bit/8bit 多档 |
| unsloth 组织页 | GGUF 动态量化打包，llama.cpp 用 | 位宽档位多，内存贴边时选择余地大 |
| ModelScope 同名仓 | 国内网络快，跨源续传备选（见 download.md） | 多为 lmstudio-community 打包，**核对格式与量化来源再用** |

安全边界沿用技能既有规则：只从模型发布方官方组织页取权重 URL，不执行来源不明的转换脚本。

## 第 3 步 · 本机架构支持现查（新模型下载前必做）

引擎不认识的架构，几十 G 下载完也加载不了。mlx-lm 支持哪些架构以**本机已装版本**为准，
一条命令现查（在装 mlx-lm 的 venv 里跑）：

```bash
python3 -c "import mlx_lm.models, os; print(sorted(f[:-3] for f in os.listdir(os.path.dirname(mlx_lm.models.__file__)) if f.endswith('.py') and not f.startswith('_')))"
```

- 输出是已装 mlx-lm 的架构模块清单（混有 base/cache 等少量辅助模块，不影响判断）。
- 核对候选模型仓库 `config.json` 的 `model_type` 是否在列：**在列才下载**；
  不在列先升级 mlx-lm 再查，仍不在列就换引擎或放弃该候选。
- 实战：Ornith 1.5 下载前先跑该预检确认 `model_type` 在列（2026-08 验证）；
  反例是 qwen3_5_mtp 架构 mlx-lm 不支持、只能走 oMLX（见 engines.md）——预检就是为拦住这类候选。
- llama.cpp 对应检查：确认该架构已进 llama.cpp 支持列表（官方 README / release notes）；
  拿不准先下最小量化档试加载，不直接下大档。

## 第 4 步 · 量化版本选择

内存门槛公式（与 engines.md 环境判定门槛同源）：**权重大小 + KV cache + 系统余量 ≤ 物理内存**。
经验：8bit 27B 级常驻约 27-28G；3bit 100G 级权重接近独占 128G 整机。

按用途的位宽建议（经验值，2026-08）：

| 用途 | 建议位宽 | 理由 |
|---|---|---|
| 编码 / agent | 8bit 优先，内存不够降 6bit | 代码任务对量化损失敏感，低位宽先掉的是结构化输出 |
| 写作 / 翻译 / 摘要 | 4-6bit 通常够 | 语言任务对位宽损失更钝感 |
| 内存贴边 | 降位宽 > 换小模型 > 硬跑（禁止） | 贴边硬跑触发换页，速度崩且拖垮整机 |

## 第 5 步 · 带宽物理学速度预估

给候选清单前先算预期速度，让客户带着量级预期做决定：

- **decode 上限 ≈ 本机内存带宽 ÷ 权重大小**（GB/s ÷ GB，量纲即 tok/s 量级）；实测约达上限 80%
  （经验系数，随架构与上下文长度浮动）。
- 各机型带宽数字与折算规则见 engines.md「Apple Silicon 带宽谱系与机型折算」。
- 实例：546GB/s 机器跑 15.8G 权重，上限约 34.5 tok/s（methodology.md 物理量程检查同源实例）。
- 预估只用于筛掉明显不可用的候选与设定预期；采纳决策以下载后实测为准。

## 产出：候选清单

给客户确认的清单，每行一个候选：

```text
模型 | 量化版本 | 权重大小 | 架构预检 | 预期速度区间 | 内存余量判断
```

客户点头才进入下载（SKILL.md 第 1 步）；机器跑不动就如实说不适合，不硬推候选。
